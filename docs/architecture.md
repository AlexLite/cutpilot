# Архитектура

```text
Браузер -> CutPilot API -> AI-провайдер (только текст и метаданные файла)
                         |-> проверка команд -> подтверждение пользователя
                         |-> атомарная передача -> watcher CutPilot -> worker FFmpeg
```

AI возвращает JSON-план, а не команду FFmpeg. Backend проверяет его по грамматике команд до того, как подтверждённая задача будет передана CutPilot.

Первая реализация использует HTTP-сервер из стандартной библиотеки Python. `/api/plan` отправляет адаптеру OpenRouter только имя выбранного файла без пути, размер в байтах, метаданные видео и текст задачи. Сервер проверяет массив команд, сам формирует имя задания и ненадолго сохраняет проверенный план в SQLite. `/api/upload` принимает видео в `AI_Cut` через уникальный временный файл, `fsync` и публикацию без перезаписи; произвольные пути и shell-команды не принимаются. `/api/jobs` требует явного подтверждения и проверяет, что размер, даты изменения и локальный отпечаток исходника не изменились. Затем он копирует снимок в случайный `.part`-файл папки watcher, выполняет `fsync` и публикует его без перезаписи существующей очереди. Исходный файл не удаляется сервером.

Сервис по умолчанию слушает `127.0.0.1`. Для доступа из LAN перед ним размещается отдельно настроенный reverse proxy. systemd запускает сервис от непривилегированного пользователя `cutpilot`, а файл окружения находится вне Git. Перед развёртыванием в LXC нужно создать пользователя, выдать только необходимые права на папки, установить Python 3, скопировать `deploy/cutpilot.service` и проверить путь watcher и доступ сервисной учётной записи.

Семантический монтаж, например поиск места, где ведущий ошибся, — отдельный будущий этап. Он потребует локальной расшифровки речи и, возможно, локального анализа сцен. Исходное видео нельзя незаметно отправлять внешнему провайдеру.
